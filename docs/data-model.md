# مدل داده (قرارداد اپ ↔ پنل/سرور آینده)

همه داده‌ها فعلاً در `localStorage` گوشی است (کلیدهای `geomat_*`) و فایل پشتیبان همین کلیدها را به‌صورت JSON دارد. API سرور در آینده باید همین ساختار را بپذیرد/برگرداند.

## آرشیو تردد و ساپورت — `geomat_logs_v2`
آرایه، جدیدترین اول. هر حضور **یک** رکورد است: ورود رکورد می‌سازد، خروج همان را کامل می‌کند (ADR-0001).

| فیلد | توضیح |
|---|---|
| `id` | عدد یکتا (میلی‌ثانیه) |
| `type` | `attendance` یا `support` |
| `company` | نام شرکت/محل |
| `date`, `day` | تاریخ شمسی با رقم فارسی و روز هفته (فقط نمایش) |
| `dateISO`, `jy`, `jm`, `jd` | تاریخ برای مقایسه و گزارش |
| `action` | `in` / `out` / `both` |
| `inTime`, `outTime` | `HH:MM` یا `null` |
| `durationMins`, `durationText` | مدت حضور (فقط وقتی هر دو ساعت هست) |
| `geo` | `{lat,lng,acc}` لوکیشن ورود یا `null` |
| `text`, `outText` | متن پیام ورود و پیام خروج |
| `closedAt` | زمان ثبت خروج |
| `actions`, `pending`, `tech`, `checklist` | فیلدهای گزارش ساپورت |
| `gap` | `{from, to, reason}`: «بین دو حضور کجا بودید؟» برای ورودِ تازه بعد از خروجِ همان روز (ADR-0001 بند ۱۲)؛ اختیاری. فقط مدیر آن را در آرشیو و اکسل می‌بیند |
| `imported` | `{at, from: {id, name}}`: گزارش ساپورتی که از «فایل آرشیو تیم» گوشی دیگری آمده (ADR-0004)؛ اختیاری |

## فایل آرشیو تیم و قرارداد همگام‌سازی آینده (ADR-0004)
تا وقتی سرور نیست، گزارش‌های ساپورت هر نفر با فایل به گوشی بقیه می‌رسد: `{app: "geomat-attendance", kind: "team-archive", v: 1, exportedAt, from: {id, name}, records: [...]}`.
- **رکوردها:** فقط `type: "support"` و فقط گزارش‌های خودِ صادرکننده؛ فیلدهای مجاز: `id, by, type, company, date, day, dateISO, jy, jm, jd, text, actions, pending, tech, checklist` (بقیه صفر یا `null`). پرونده فنی، رمز و تردد هرگز در فایل نیست.
- **کلید یکتا:** `by.id|id` (id زمان ثبت است و بین دو گوشی تکراری می‌شود). ورود فقط اضافه می‌کند؛ رکورد موجود هرگز عوض یا حذف نمی‌شود.
- **محدودیت:** حداکثر ۲ مگابایت و ۲۰۰۰ رکورد؛ اگر آرشیو از ۵۰۰۰ رکورد بیشتر شود، فایل وارد نمی‌شود (هیچ رکوردی برای جا باز کردن کنار نمی‌رود).
- **سرور:** همین شکل رکورد و همین کلید یکتا. API همگام‌سازی باید فقط-افزودنی باشد و `by.id` را از نشست سرور بگذارد، نه از بدنه درخواست.

## پرونده فنی شرکت‌ها — `geomat_inventory_v1`
```json
{ "schema": 2,
  "companies": [ { "id": "uuid", "name": "مشتری دور", "deleted": false, "createdAt": "ISO",
                   "createdBy": { "id": "...", "name": "..." },
                   "history": [ { "at": "ISO", "by": { "id": "...", "name": "..." }, "action": "create|restore", "name": "..." } ] } ],
  "items": [ {
    "id": "uuid-v4",
    "company": "کرانه",
    "section": "network | access | remotes | hosts | servers | apps | users",
    "data": { "...": "متن ساده، فیلدها طبق بخش" },
    "secrets": { "password": { "v": 1, "iv": "base64", "ct": "base64" } },
    "createdAt": "ISO", "updatedAt": "ISO", "updatedBy": { "id": "...", "name": "..." },
    "deleted": false,
    "history": [ { "at": "ISO", "by": { "id": "...", "name": "..." }, "action": "create|edit|delete|restore",
                   "data": { }, "secrets": { } } ]
  } ] }
```
- `companies` فقط پرونده‌هایی است که در خود پرونده فنی ساخته شده‌اند. محل‌های تردد (`geomat_companies_v2`) هم خودکار پرونده دارند.
- فیلدهای هر بخش در `INV_SECTIONS` داخل `index.html` تعریف شده‌اند. فیلدهای `ref` (میزبانِ سرور، سرورِ برنامه) `id` آیتم دیگر را نگه می‌دارند.
- **`history` فقط-افزودنی است:** هر تغییر با `pushVersion()` یک نسخه کامل اضافه می‌کند و آخرین نسخه همان وضع فعلی است. حذف نرم است (`deleted: true` به‌اضافه نسخه «delete»).
- **همگام‌سازی آینده:** ادغام بر اساس `id` آیتم و اجتماع نسخه‌های `history` (کلید: `at` + `by.id`) انجام می‌شود. سرور هیچ نسخه‌ای را پاک نمی‌کند.
- فیلترها از داده ساخته می‌شوند: دامین/ورک‌گروپ از `network.kind`، ESXi از `hosts.hypervisor`.

## حساب‌ها — `geomat_team_v1`
```json
{ "schema": 1,
  "users": [ { "id": "uuid", "name": "رضا", "phone": "09121234567", "role": "admin | tech", "active": true,
               "salt": "base64(16B)", "iter": 310000, "wrapped": { "v": 1, "iv": "...", "ct": "..." },
               "createdAt": "ISO", "createdBy": { "id": "...", "name": "..." } } ],
  "log": [ { "at": "ISO", "by": { }, "action": "team-create|user-add|user-enable|user-disable|password|team-import", "detail": "..." } ] }
```
- `wrapped` همان «کلید تیم» (۳۲ بایت تصادفی، AES-GCM-256) است که با کلیدِ ساخته‌شده از رمز همان نفر (PBKDF2-SHA256) رمز شده. همه `secrets` با کلید تیم رمز می‌شوند.
- «فایل تیم» (`{app, kind:"team", team}`) همین `users` است، بدون `log` و بدون هیچ رمزی.
  - گوشی تازه (بدون `geomat_team_v1`): از صفحه ورود وارد می‌شود.
  - گوشی دارای تیم: فقط بعد از ورود («حساب من ← به‌روزرسانی فایل تیم»)، با رمز خود کاربر در فایل تازه؛ کلید تیمِ بازشده باید همان کلید فعلی باشد. اگر واردکننده مدیر باشد، `users` جایگزین می‌شود. اگر تکنسین باشد، فقط رمز حساب خودش و حساب‌های تازه (با نقش تکنسین) پذیرفته می‌شود؛ نقش، فعال بودن و رمز بقیه همان قبلی می‌ماند. `log` قبلی می‌ماند (یک ردیف `team-import` اضافه می‌شود).
- `phone` شناسه ورود به کل برنامه است (نرمال‌شده `09xxxxxxxxx`)؛ همین با رمز بعداً به دیتابیس سرور می‌رود و پنل مدیریت آن را تغییر می‌دهد. حساب‌های پیش‌نمایش بدون شماره، در اولین ورود شماره می‌گیرند.
- `geomat_last_phone`: آخرین شماره واردشده روی این گوشی (فقط برای پر کردن فرم ورود).
- `geomat_bio_v1` (فقط وب): `{ [userId]: { credId, salt, wrapped } }`؛ کلید تیم زیر کلید PRF پس‌کلید پلتفرم. در APK همین در Android Keystore و SharedPreferences برنامه است.
- `geomat_vault_fail_v1`: شمارنده رمز اشتباه (بعد از ۵ بار، ۳۰ ثانیه صبر).
- `geomat_vault_meta_v1`: فقط در پیش‌نمایش اول 1.4 بود (یک رمز اصلی). با اولین ورود مدیر منتقل و پاک می‌شود.

## تنظیمات — `geomat_settings_v1`
`reminderTime`: یادآوری خروج همان روز در این ساعت؛ ورودی که بعد از این ساعت ثبت شود (شیفت عصر/شب) فردا همین ساعت یادآوری می‌گیرد (`exitReminderAt()`). از لحظه ورود هم یک اعلان ماندگارِ «حضور» در APK هست.

`{ reminderTime, workStart: "09:00", workEnd: "17:00", thuEnd: "14:00", holidays: ["YYYY-MM-DD", ...], theme: "dark|light|system" }`. گزارش ماهانه اضافه‌کار و کسر کار را از همین‌ها حساب می‌کند (ADR-0001 بند ۱۰).

## رکوردهای آرشیو: چه کسی
`by: {id, name}` (ثبت‌کننده) و `closedBy` (ثبت خروج)، از نشست ورود. فیلتر «👤» شخص روی آرشیو، اکسل (ستون «ثبت‌کننده») و گزارش ماهانه اعمال می‌شود؛ اضافه‌کار و کسر فقط وقتی رکوردها مال یک نفرند حساب می‌شود. `actions`/`pending`/`tech` فقط در رکورد ساپورت پر می‌شوند.

## پیام‌رسان — `geomat_chat_messages_v1`
آرایه `{id, sender, by: {id, name} | null, isMine, channel: attendance|support|general, ts, text}`، حداکثر ۱۰۰ پیام. `by` از 1.4؛ «من» بودن پیام با `by.id` حساب می‌شود (گوشی مشترک). پیام‌های قدیمی بدون `by` با `isMine` یا نام فرستنده.

## به‌روزرسانی
`geomat_schema_version` (الان `14`) و `geomat_backup_pre_1_4` (`{at, from, data}`: کپی کامل پیش از اولین اجرای 1.4؛ در فایل پشتیبان نمی‌آید).
- کپی پیش از به‌روزرسانی ۳۰ روز بعد خودکار پاک می‌شود. وقتی حافظه پر است، پیش از هر رکورد واقعی همین پاک می‌شود (`storeItem()` در `13-migrations.js`، برای آرشیو، پرونده فنی و حساب‌ها).

## فضا
localStorage در Chromium و WebView حدود ۵٫۲ میلیون نویسه برای همه کلیدها جا دارد. تنظیمات درصد مصرف را نشان می‌دهد و از ۸۰٪ هشدار می‌دهد. تاریخچه پرونده فنی فقط-افزودنی است و کوتاه نمی‌شود؛ برای داده‌های بزرگ‌تر، انتقال به IndexedDB یا سرور لازم است.

## نسخه دوم روی دیسک (فقط APK)
WebView نوشته‌های localStorage را با تأخیر روی دیسک می‌برد و با ری‌استارت گوشی تغییرهای آخر گم می‌شدند (گزارش مالک).
- **نوشتن:** هر نوشتن یا حذف در کلیدهای `geomat_*` همان لحظه و اتمیک (فایل موقت، `fsync`، rename) در `filesDir/geoteam_store/<key>` هم انجام می‌شود (پل: `storeSet`/`storeRemove`). شمارنده `seq` در فایل `.seq` بالا می‌رود و `geomat_mirror_seq` همان را در localStorage نگه می‌دارد.
- **فایل‌های کمکی:** حذف هر کلید یک نشانه `<key>.del` می‌گذارد. فایل `.complete` فقط وقتی هست که همه داده یک بار بی‌خطا نوشته شده باشد؛ هر نوشتنِ ناموفق آن را پاک می‌کند.
- **شروع برنامه:** `restoreFromMirror()` اول `init` اجرا می‌شود.
  - **نسخه دوم کامل نیست** (اولین اجرا بعد از آپدیت، یا یک نوشتنِ ناموفق): از داده فعلی دوباره ساخته می‌شود و localStorage دست نمی‌خورد.
  - **نسخه دوم کامل است و `seq` آن بیشتر از `geomat_mirror_seq` است:** کلیدهای نسخه دوم نوشته می‌شوند و فقط کلیدهایی پاک می‌شوند که نشانه حذف دارند.
- `geomat_mirror_seq` مال همان گوشی است: در فایل پشتیبان، کپی پیش از به‌روزرسانی و بازگردانی نمی‌آید. وب‌اپ این لایه را ندارد.
