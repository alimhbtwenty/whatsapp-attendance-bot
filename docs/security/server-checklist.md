# چک‌لیست امنیتی اتصال به سرور (پیش از انتشار)

بر پایه OWASP ASVS 4 سطح ۲. برای هر بند یک تست تعریف شده که با آمدن سرور باید **خودکار** در CI اجرا شود (پوشه پیشنهادی `tests/server/`). هیچ بندی بدون تست سبز «انجام‌شده» حساب نمی‌شود.

| # | الزام | تست پذیرش |
|---|---|---|
| 1 | فقط HTTPS (TLS 1.2+)، HSTS با preload، بدون محتوای مختلط | درخواست http → 301 به https؛ هدر `Strict-Transport-Security: max-age>=31536000; includeSubDomains` |
| 2 | ورود با شماره + رمز؛ رمز روی سرور با Argon2id (یا scrypt) ذخیره | ثبت حساب و بررسی دیتابیس: هیچ رمز/هش ضعیف (MD5/SHA1/bcrypt<10) |
| 3 | محدودیت تلاش ورود به‌ازای شماره و IP (مثلاً ۵ در ۱۵ دقیقه) + پیام یکسان | ۶ بار رمز اشتباه → 429؛ شماره ناموجود و رمز اشتباه پاسخ و زمان یکسان (±۵۰ms) |
| 4 | ورود دومرحله‌ای برای مدیر (TOTP یا پیامک) | ورود مدیر بدون کد دوم → رد |
| 5 | نشست: توکن کوتاه‌عمر (≤۱۵ دقیقه) + refresh چرخشی؛ ابطال با خروج و غیرفعال شدن حساب | توکن بعد از غیرفعال کردن حساب → 401 در کمتر از ۱ دقیقه |
| 6 | **کنترل دسترسی سمت سرور** برای هر endpoint (تکنسین: خواندن/افزودن/ویرایش؛ مدیر: حذف، تاریخچه، کاربران) و به تفکیک شرکت | ماتریس نقش×endpoint: هر ترکیب غیرمجاز → 403 (تست خودکار برای همه routeها) |
| 7 | **تاریخچه غیرقابل پاک‌شدن روی سرور**: جدول نسخه‌ها append-only (بدون UPDATE/DELETE حتی برای مدیر)، با زمان سرور | تلاش DELETE/UPDATE روی جدول نسخه‌ها از API و از نقش دیتابیس برنامه → رد |
| 8 | رمزنگاری سرتاسری پسوردها: سرور فقط `secrets` رمزشده و `wrapped` را می‌بیند؛ کلید تیم هرگز به سرور نمی‌رود | جستجوی هر پسورد تست در دیتابیس، لاگ‌ها و ترافیک → پیدا نشود |
| 9 | اعتبارسنجی ورودی سمت سرور با schema (همان `docs/data-model.md`)؛ سقف اندازه درخواست | payload خراب/بزرگ → 400/413؛ تست fuzz روی همه endpointها |
| 10 | هدرهای امنیتی پنل: CSP سخت، `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors 'none'` | اسکن خودکار هدرها |
| 11 | CORS فقط دامنه پنل و برنامه | درخواست از Origin دیگر → رد |
| 12 | لاگ دسترسی امن: چه کسی، کی، کدام آیتم/پسورد را دید یا عوض کرد؛ بدون ثبت پسورد یا توکن | دیدن پسورد → رکورد لاگ؛ grep لاگ برای توکن/پسورد → خالی |
| 13 | پشتیبان رمزشده و آزمایش‌شده دیتابیس + تمرین بازیابی | بازیابی ماهانه در محیط تست |
| 14 | وابستگی‌ها: lockfile، `npm audit`/SCA در CI، ایمیج داکر حداقلی و بدون root | CI قرمز با آسیب‌پذیری high/critical؛ کانتینر با کاربر غیر root |
| 15 | داکر: secretها از env/secret store، نه داخل ایمیج؛ پورت دیتابیس بیرون باز نباشد | اسکن ایمیج (trivy)؛ nmap از بیرون فقط 443 |
| 16 | همگام‌سازی: ادغام نسخه‌ها مثل `mergeInventoryData` (اجتماع، بدون حذف)؛ زمان سرور مرجع | دو دستگاه با ویرایش هم‌زمان → هر دو نسخه در تاریخچه |
| 17 | خاموش کردن `android:allowBackup` پس از اتصال سرور | بررسی manifest در CI |
| 18 | تست نفوذ مستقل پیش از انتشار عمومی | گزارش بدون یافته high/critical باز |
