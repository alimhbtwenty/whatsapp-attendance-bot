# ADR-0004: آرشیو ساپورت مشترک تیم (فایل، بعداً سرور)

## Status
Accepted (تصمیم مالک)

## Date
2026-10-13

## Context
مالک: «باید برای قسمت ساپورت هم آرشیو داشته باشیم … تا توسط بقیه تکنسین‌ها و مدیر قابل دسترسی باشند.»
گزارش‌های ساپورت از قبل در `geomat_logs_v2` گوشیِ همان نفر ذخیره می‌شدند، ولی برنامه سرور ندارد و گوشی دیگر آن‌ها را نمی‌دید. مالک بین «فایل آرشیو تیم»، «صبر تا سرور» و «هر دو»، گزینه **هر دو** را انتخاب کرد.

## Decision
1. **آرشیو:** فیلتر نوع «همه / تردد / ساپورت» کنار فیلتر شرکت؛ کارتِ گزارشِ نفر دیگر نام او را دارد.
2. **فایل آرشیو تیم:** «📤 فایل آرشیو تیم» فقط گزارش‌های ساپورتِ خودِ کاربر را در یک JSON می‌گذارد (`docs/data-model.md`). «📥 افزودن فایل آرشیو تیم» برای همه (تکنسین و مدیر) است.
3. **ورود فقط-افزودنی:** کلید یکتا `by.id|id`؛ رکورد موجود عوض یا حذف نمی‌شود؛ هر فیلد با نوع و اندازه بررسی می‌شود و فیلد ناشناخته دور ریخته می‌شود؛ رکوردِ غیر ساپورت پذیرفته نمی‌شود. اگر آرشیو جا نداشته باشد، فایل وارد نمی‌شود (هیچ رکوردی کنار نمی‌رود).
4. **جداسازی:** گزارش وارد‌شده فقط در آرشیو و اکسل است؛ در جفت شدن ورود و خروج، سلام اول روز، ورود باز و اضافه‌کار نقشی ندارد.
5. **حذف:** حذف از آرشیو فقط همان رکورد را برمی‌دارد (`deleteLogItem(id, byId)`)، حتی اگر رکورد دیگری همان id را داشته باشد.
6. **سرور (آینده):** همین شکل رکورد و کلید یکتا قرارداد همگام‌سازی است؛ `by` روی سرور از نشست گذاشته می‌شود.

## Consequences
- فایل امضا ندارد؛ کسی که فایل را دستکاری کند می‌تواند نام نویسنده را جعل کند. این ریسک تا سرور پذیرفته شد، چون فایل فقط گزارش ساپورت اضافه می‌کند و به تردد، حساب‌ها یا پرونده فنی دسترسی ندارد.
- تست: `tests/e2e/support-archive-share.js`.
